# Frame effects and portable bundles, draft v1

This document specifies a **future contract**, not a claim that the current player, renderer, or exporter implements it. The initiative's D02 and D08 are authoritative for scope. MUST, SHOULD and MAY are normative. Schemas use JSON Schema draft 2020-12 and reject unknown fields except explicitly extensible maps.

## Effect instance

An effect implementation exposes `mount(root, {width, height, fps, seed, assets})`, `seek(frame): Promise<void>`, and `dispose(): void`. `root` is the host DOM element; dimensions are positive pixels, fps is positive, seed is a recorded uint32, and assets are pre-resolved local assets. Mount establishes the instance; seek accepts a nonnegative integer and represents time `frame / fps` seconds. A visible interval is `[startFrame,endFrame)`. Seek MUST settle asset loading and visual state before its promise resolves. Repeated, backward, random and parallel evaluations under the same pinned environment MUST produce reproducible state within documented tolerances. Pure time formulas and baked deterministic trajectories are allowed; ambient wall clock and unseeded randomness are forbidden. Dispose releases resources and is safe at end of use. An implementation MUST document any concurrency restrictions necessary to achieve this result.

The versioned `effect-descriptor` declares the effect ID, version and JSON Schema for its parameter object; the `effect-config` references that identity, parameters and visibility interval. Validators MUST validate parameters against the matched descriptor and reject an unknown ID/version, invalid parameters, or endFrame < startFrame. Use one shared implementation in DOM player and renderer, adapting existing React layouts. Preserve the existing mount cleanup return API; add a separate controller API exposing seek, pause and dispose. Server HTML alone is not evidence of canvas or WebGL output.

## Portable bundle v1

A directory or ZIP contains `videoml-project.json`, `source/`, `assets/`, `audio/`, `timing/`, `dependencies.lock.json`, and `notices/`. The manifest conforms to `portable-bundle.schema.json`; paths are relative POSIX paths. `files` covers every source, asset, font, audio, timing, notice and dependency-lock file, exactly once; each record contains the SHA-256 of file bytes and media type. `assets` is a subset of matching `files` records with identical digest and media type. The required `composition` object records the selected source composition `id`, one frozen script, one resolved timing file, and assembled audio or null; multi-composition export requires an explicit selector, and import verifies the selected identity; its script, timing, audio, and entry paths MUST reference listed files. `timing` contains exactly the composition timing path; `audio` contains exactly the assembled audio when present and all distinct referenced segment audio paths. No unlisted payload, missing file, symlink, absolute, backslash, traversal, dot or duplicate normalized path is permitted. Verify every digest before use. JSON Schema cannot verify file existence, symlinks, uniqueness by path, subset consistency or content: the importer MUST perform these checks.

For the content digest, remove `contentDigest` from the manifest, sort the `files` and `assets` arrays by path in Unicode code point order, preserve every other array order, canonicalize the resulting JSON with RFC 8785 JSON Canonicalization Scheme (JCS), concatenate the sorted `files` array’s lowercase hexadecimal SHA-256 strings in that order with no separator, and SHA-256 the UTF-8 bytes of the canonical manifest followed by that ASCII concatenation. This definition avoids self-hashing. Dependency and font version maps are pinned; the lock file is also hashed. Generated narration and frozen resolved timing travel with the bundle; rendering does not require TTS credentials or network fetches.

Before extraction, reject ZIPs with compressed size >250 MiB, expanded size >1 GiB, >10,000 files, any file >250 MiB, duplicate normalized paths, symlinks or unsafe paths. Enforce limits while streaming, including actual bytes, not just header claims. Sanitize SVG external references and scripts; reject unsupported active formats. Local trusted projects MAY compile TS during preparation. Hosted pilot input is declarative XML with built-in or approved effect IDs and validated data only; reject scripts, handlers, custom components, executable expressions, HTML injection, external URLs and TS entrypoints. User data MUST NOT become code. The supervisor stages and validates the bundle, then launches the pinned allowlisted worker without credentials, metadata access or network, and uploads verified output separately. No arbitrary installs or setup hooks. Both directory and ZIP exports remain usable without a Babulus account.

`dependencies.lock.json` is a data-only object with exactly `dependencies` and `fonts` maps. A dependency key is the canonical npm package name followed by `@` and an exact version; its value is `sha256:` followed by the lowercase content digest. Font keys are declared font asset IDs and values use the same prefix with the verified font-byte digest. The manifest maps must equal the lock maps. For a package content digest, enumerate its shipped regular files recursively, excluding nested `node_modules`; paths are normalized POSIX NFC paths with case collisions rejected. Internal symlinks and special files are invalid. Sort records by path in Unicode code point order, represent each as `{"path":...,"sha256":...}`, serialize the array with JCS to UTF-8, and SHA-256 those bytes. A trusted package manager's top-level package link may be resolved to its real package root; payload links remain invalid. The runtime closure starts at the CLI, toolchain, renderer, shared, stdlib and player packages, follows non-development dependencies and required peers, and includes optional dependencies and peers when present. Missing optional packages are allowed; malformed or unreadable present packages are not. Offline rendering checks the installed runtime closure against these identities before execution. Browser, encoder, operating-system and fallback-font identities are release-environment evidence rather than portable bundle pins; cross-host pixel or bit reproducibility requires the pinned Linux release gate.

Directory and ZIP staging require Python 3.9 or later and supported descriptor-relative no-follow traversal and atomic no-replace publication primitives. The destination parent and its ancestors must be trusted against untrusted writers; a private same-user parent is required. This boundary does not defend against a malicious process with the same UID or root. Lost publication confirmation requires reconciliation against the expected digest and MUST NOT trigger automatic deletion or retry.

A trusted custom-source composition MAY add the four roles `normalizedSource`, `sourceClosure`, `browserBundle`, and `customComponents` together. `normalizedSource` is a hashed JSON data snapshot; `sourceClosure` is a bounded explicit list of hashed source files including the entry; `browserBundle` is a hashed JavaScript file or null; and `customComponents` lists unique string IDs and versions. A null browser bundle requires an empty component list. The entry, script, timing, normalized snapshot, browser bundle, dependency lock, and assembled audio occupy distinct paths; source closure may include the entry but cannot alias other executable or data roles. Source media types and extensions must match their roles. A source snapshot is not proof that executable source produced it: inert local inspection reports pending trusted execution, and publication or rendering requires explicit local authorization to compile and execute the closed source and compare its normalized result to the snapshot. Hosted validation rejects custom executable source and browser bundles before execution. These portability checks are not a sandbox for trusted local code.

Trusted custom browser factories use host ABI v1. The factory registers declared unique component IDs and versions against the renderer's shared React, JSX runtime and frame/config/context hooks; builtin collisions are invalid. Each registration explicitly declares synchronous behavior or a per-mounted-instance controller with awaitable `settle` and `dispose`, accepting an abort signal. Normal and shader scene captures use the same verified factory; the compositor never loads it. Cancellation and timeouts require owner cleanup and do not promise revocation of arbitrary same-realm code that ignores cancellation.

Hosted eligibility is a separately computed validation report containing an eligibility boolean, a policy version, and path-specific reasons. A portable local bundle can be hosted-ineligible. Hosted mode re-evaluates the current fixed policy before admission; no stored eligibility claim changes the content digest or grants authority. Hosted input is limited to classified built-in component, transition, style and asset-reference schemas; unknown surfaces fail closed.

ZIP and filesystem enforcement is a P17 implementation gate. These schema and reference vectors do not implement or demonstrate ZIP import safety.

## XML frame-effect binding (draft)

A `frame-effect` is a component within a scene, layer, sequence, stack, or transition, using the existing XML timing and ID rules:

```xml
<vml id="example" fps="30" width="1280" height="720">
  <scene id="scene" duration="4s">
    <frame-effect id="effect" effect-id="videoml/echo-smear" effect-version="1" props='{"parameters":{"color":"#71f5a7"}}' start="0f" duration="120f" />
  </scene>
</vml>
```

The `effect-id` and exact `effect-version` MUST resolve in an approved registry; the `props` JSON object MUST contain only a `parameters` object. Its content MUST be plain finite data, recursively rejecting prototype-sensitive keys and executable expressions, and MUST validate against the registered descriptor. Unknown identities, versions, invalid parameters, or missing required pre-resolved assets MUST fail explicitly. The registry may be explicitly supplied by a trusted caller; the default built-in registry is fixed by the implementation and MUST NOT load code named by the XML.

Start and duration use the ordinary component timing grammar, including frame units and inherited container timing. Frozen timing, when provided, is authoritative and uses the ordinary qualified component ID. The effect receives composition-absolute integer frames, not an independent local clock; visibility is half-open. Dimensions, frame rate, seed, and approved assets come from the composition and its caller. Seek MUST settle before capture, and disposal MUST release resources even after cancellation or failure. This draft describes the intended binding; implementations and release parity require separate verification.

### Local effect assets

An XML root MAY declare `<assets><asset id="font" src="assets/Geist-Latin.woff2" media-type="font/woff2"/></assets>`. The container is metadata and does not participate in timeline or normalized component IDs. Each ID is a unique asset-map key. Paths are relative POSIX paths resolved against the source XML directory; absolute paths, backslashes, traversal, URL schemes, query strings and fragments are invalid. The initial supported media types are WOFF2 fonts and PNG, JPEG, WebP or restricted SVG images. A composition MAY declare at most 32 assets, with at most 16 MiB per asset and 64 MiB total.

Generation copies verified bytes into content-addressed files adjacent to the generated script and records `id`, relative `path`, `mediaType`, and SHA-256 in `script.meta.assets`; source absolute paths MUST NOT appear in generated artifacts. Node rendering requires the script directory as `assetBaseDir` when declarations exist, verifies file bytes and hashes, and passes pre-resolved data or blob URLs to effects without browser network access. A programmatic override that conflicts with a declared asset MUST fail rather than silently change its identity.

A browser XML player MAY prepare declarations from same-origin resources using an explicit asset base URL or the document base URL. Alternatively, a trusted caller MAY provide matching pre-resolved local data or blob URLs. Preparation MUST settle before the first effect seek, reject missing or mismatched assets, enforce the bounds while reading, and release owned resources on cancellation or disposal. ZIP import and stronger hostile-filesystem isolation remain P17 responsibilities.

For player effects, the frozen `generationSeed` takes precedence over a trusted explicit `effectSeed`, followed by an authored `voiceover` seed and then zero. An authored random seed requires frozen timing or an explicitly supplied resolved seed. Generation records its resolved seed in script metadata so script-only rendering can reproduce the same effect without starting a speech provider; renderers use frozen timing first, then a trusted explicit override, then that script seed, and finally zero.

The normal shared mount path supplies a fresh immutable `timing` context containing the validated `startFrame` and `endFrame`, and uses copies of those same bounds for visibility. The context field is optional for compatibility with direct mounts; new effects requiring placement timing MUST fail with `EFFECT_TIMING_UNAVAILABLE` when it is absent. Placement-relative adapters calculate `(absoluteFrame - startFrame) / fps` and clamp to authored timeline endpoints. Existing version 1 effects retain their original absolute-frame behavior. XML authored seconds convert using `floor(startSeconds * fps)` and `ceil(endSeconds * fps)`; subsequent mutation of caller configuration cannot change placement.

A renderer MUST cull a frame effect using the rounded half-open frame interval rather than exact-second component culling. This corrects fractional boundary frames while leaving ordinary component culling and existing effect interpolation unchanged.

A player MUST treat the `frame-effect` element as a reserved effect host, not an unknown-component placeholder; placeholder content must not shift or cover the mounted effect.

An effect descriptor MAY declare data-only `sceneInputs` pairs identifying scene-ID and absolute-frame parameter names. Both fields absent select a separate input mode; a partial pair is invalid. Source scenes must exist. Preparation rejects scene-reference cycles, traversal depth above eight and more than four distinct scene/frame snapshots. Snapshot inputs are immutable scene captures at their declared absolute frames, not the changing destination frame. A preview without a trusted native-pixel provider fails `SCENE_CAPTURE_UNAVAILABLE`; no HTML rasterization substitute is implied. Each capture returns an owned `{bitmap, close()}` handle, and the consumer keeps it open while its one derived canvas copy remains live, then closes it. Late results after cancellation are closed.

A trusted custom-source bundle MAY carry `composition.customEffects` as bounded declarative effect ID/version and `sceneInputs` metadata, bound by its content digest. Its browser registration must match these declarations. XML and hosted flows do not grant custom executable registration. Preparation is private to the composition and topologically captures dependencies before consumers using isolated browser-painted scenes; it must enforce dimension, PNG, aggregate encoded and decoded budgets and a 10-second queue-through-decode-and-cleanup deadline. Later cached acquisitions have their own deadline. See the implementation contract for exact bounds and ownership.
