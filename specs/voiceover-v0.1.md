# Voiceover and local speech bridge, draft v0.1

This is a normative target, not a statement that the existing implementation already supports the new defaults, bridge, speed, pronunciation XML, exact trims or frozen timing. Existing XML roots `vml`, `videoml` and `video-ml`, and existing `voiceover`, `cue`, `voice`, and `pause` structures remain compatibility inputs; no replacement XML syntax is introduced. Draft additions are `speed` on `voiceover` and `pronunciation` children carrying either `grapheme`/`alias` or `grapheme`/`phoneme`/`alphabet`. Exact aliases work with every provider; phonemes require advertised support or fail explicitly. Retain original and expanded text. The JSON voiceover schema represents normalized configuration, not an alternative XML syntax.

New projects default to provider `auritus`, voice `kokoro:af_heart`, speed 1, seed 0, and sample rate 24000 Hz. Visual-only documents instantiate no provider. Paid providers require explicit choice; missing credentials or CI MUST NOT silently select dry-run. Explicit test dry-run artifacts are marked simulated. Existing projects' explicit settings remain effective.

## Process protocol

Launch `python -m auritus.speech_bridge` with argv and no shell, one process per generation run, serialize requests and close at completion. UTF-8 newline-delimited JSON messages conform to `speech-request` and `speech-response` schemas; stdout contains only JSON and diagnostics go to stderr. IDs correlate requests and responses. A capabilities request MAY specify voice (default `kokoro:af_heart`) and voicesDir; the response describes one selected backend and voice. Capabilities report installation, runtime readiness, backend, model identity (null when unavailable), revision (null if unavailable), Auritus version, voices and supported options without model download. A null model ID or revision requires a nonempty cache-disabled reason. Synthesis writes `speech.wav` and `speech.json` atomically under a unique caller-supplied segment directory and returns relative paths, WAV and PCM digests, decoded sample count/rate/duration, block segments and provenance. Block segments are not word alignment. Namespaced extensions MUST NOT override core fields.

A revision unavailable as null requires a nonempty cache-disabled reason. Reject nonfinite numbers and inconsistent segment ranges, duration versus sample count/rate, missing files, digest mismatch, paths escaping the segment directory, malformed JSON, wrong protocol or ID. Request errors use the five named codes in the response schema and leave the process alive. Clean EOF exits 0; fatal protocol/process failure exits nonzero. A 300-second per-segment timeout kills the process group, invalidates the request, removes partial files and fails the run; do not silently restart. Nonzero exit fails the run. Model setup is explicit; generation never downloads models or falls back to paid synthesis. CI may explicitly mock the protocol; real Kokoro smoke remains a release gate.

## Samples, timing and cache

Synthesize text segments separately. Resample each once with pinned FFmpeg to signed 16-bit mono PCM at `sampleRateHz`, then count decoded samples. Apply segment trim override or voiceover default trim exactly, rounded `floor(seconds * sampleRate + 0.5)`; reject negative or nonfinite trim and trim greater than or equal to the segment sample count. Keep original untrimmed cached audio. This intentionally corrects the legacy discrepancy: scene trim was guarded by measured trailing silence while narration trim was unconditional. Insert fixed or Gaussian pause silence after trimmed segments and lead-in silence once at composition start; reject lead-in with explicit scene times. Resolve cues from actual assembled sample offsets, never estimated TTS duration. Reject same-track narration overlap unless separate tracks are explicitly configured.

Gaussian pauses sample in document order using the existing Mulberry32 `makeRng` (increment `0x6d2b79f5`, the existing integer mixing operations) and Box–Muller `sqrt(-2*ln(u))*cos(2*pi*v)`, drawing nonzero u then nonzero v. Clamp to configured min/max and then zero; round to samples with halves upward. Reject nonfinite parameters, negative standard deviation or min > max. Explicit random mode draws one uint32 from system entropy at generation and records it; never resample for playback or export. Persist chosen sample counts and generation seed. Explicit numeric seeds retain legacy sampling behavior.

For a nonempty interval, startFrame = floor(startSample / sampleRateHz * fps) and endFrame = ceil(endSample / sampleRateHz * fps); visibility is half-open. Zero-duration intervals show no frames. Thus 0.01–0.04 seconds at 30 fps covers frames 0 and 1. Frozen resolved timing is authoritative in both player and export; retain exact sample offsets. Consumers MUST validate ordered offsets and frames, sample-derived frame arithmetic, no invalid overlap, and referenced audio hashes beyond schema validation.

VideoML cache v1 uses SHA-256 of canonical sorted JSON containing pronunciation-expanded text, provider/backend/model and resolved model revision, Auritus version, reference audio and transcript content digests, voice, speed, seed, and output audio settings. Output identity includes SHA-256 of the resolved FFmpeg executable bytes and SHA-256 of its full version/build-configuration output; a change in either invalidates reuse. Record those digests and the full version/build output in `videoml.ffmpeg` provenance. A release requires a pinned FFmpeg build; recording an observed build is not itself a pin. If revision cannot be resolved, disable cache reuse and report why. Preserve Auritus remote `content_hash` and speech `request_key` unchanged as provenance. Emit and verify both `audioSha256`, the SHA-256 of all WAV file bytes, and `pcmSha256`, the SHA-256 of signed 16-bit little-endian interleaved mono sample bytes excluding the WAV header. Auritus provenance includes its required SHA-256 `requestKey` and nullable SHA-256 `contentHash` (null for local synthesis); preserve both unchanged. Frozen audio is used for rendering; cross-hardware regeneration is not guaranteed bit-identical.

## Frozen timeline and provenance

Resolved timing includes durationFrames, fps, and `audioTotalSamples`, the authoritative length of the assembled mono PCM including leading, interior, and trailing silence. A silence-only composition may have no segments and a nonzero audioTotalSamples. It includes arrays of scenes, cues, layers, components and transitions with stable globally unique IDs and half-open frame intervals. Segments have stable IDs, a cueId referring to an existing cue, exact half-open sample intervals, and derived frame intervals. All intervals must be ordered and lie within the composition; all IDs must be unique across categories. Empty narration is valid for a visual-only composition. Segment track names identify narration tracks; same-track sample intervals must not overlap. Any cross-reference must resolve. These invariants require semantic validation in addition to schema validation.

Segment provenance is provider-discriminated. Every provider records provider name, simulated status, WAV and PCM digests, and namespaced extensions. Auritus additionally records backend, model, revision, Auritus version, voice, speed, seed, reference digests, cache-disabled reason, requestKey and contentHash. Paid providers are explicit and may put provider-specific data under a namespaced extension; dry-run has provider `dry-run` and simulated true. The segment and provenance digests must match and must be checked against actual WAV bytes and decoded PCM.

### Qualified source identities

Resolved IDs encode source identity as `kind:` followed by compact JSON encoding of an array of the original path IDs, preserving their exact Unicode strings. For example, a layer is `layer:["sceneId","layerId"]`, and a component inside it is `component:["sceneId","layerId","componentId"]`. Scene and transition IDs have one path element; this toolchain currently requires scene IDs and cue IDs to be globally unique, so cues use `cue:["cueId"]`. Delimiters within source IDs have no special meaning. Producers and consumers use the shared `@videoml/shared/resolved-timing` encoder and reject duplicate, malformed or mismatched IDs.

Current source voice segments have no individual IDs, so their IDs use `segment:["cueId",0]`, with the zero-based segment position as a JSON number. This positional index is internal to the frozen audio record and MUST NOT be used to match a DOM element. Narration edits and reordering require regeneration. Local editable preview may change non-timing visual content while using frozen times; P15 checks ordered source IDs and timing/audio integrity, not all source content. Portable bundle v1 (P17) binds source, script, timing and audio through its manifest hashes. If the source gains explicit segment IDs, preserve those IDs instead of inventing positional ones.

Transition-owned layers use `transition-layer:["transitionId","layerId"]`; transition-owned components use `transition-component:["transitionId","componentId"]` or `transition-component:["transitionId","layerId","componentId"]`. These distinct kinds prevent collisions with scene-owned IDs.

Frozen browser playback verifies every segment WAV and PCM hash and the assembled composition bytes before mounting. The verified composition is the sole audible track; native source audio is removed, while source video remains visible and is muted. Unsupported active source scripts and event handlers fail explicitly. Export verifies bounded paths and stages verified composition bytes before encoding. Portable hosted visual-asset network isolation is a P17 concern.

### Normalizing missing visual IDs

XML is normalized before sequence and stack structures are flattened. The shared pure `normalizeSourceTree` and `normalizeSourceElement` APIs preserve explicit IDs and assign missing component, layer, and transition IDs under the reserved `@videoml:auto:` prefix. The suffix is compact JSON `[parentIdentity, wrapperPath, kind, sameKindSiblingOrdinal]`. The root parent identity is compact JSON `["root",rootId]` (empty string when absent). On entering a scene, narration, layer, or transition, the new parent identity is compact JSON `[previousParentIdentity,nodeKind,normalizedId]` and wrapperPath resets. wrapperPath is an ordered array of `[sequenceOrStackKind, sameKindSiblingOrdinal]` pairs. Ordinals count element nodes of the same kind in source order; whitespace, attribute ordering and component tag spelling do not affect them. Scene, narration and cue IDs remain required. An authored reserved ID is accepted only when it exactly equals the ID recomputed for that position; stale or forged reserved IDs fail. XML and browser adapters use the same normalizer before flattening. Already-normalized XML IDs are carried unchanged into script and frozen timing; raw TypeScript compositions are normalized once at their own authoring boundary, never by re-normalizing an already flattened XML script.

An implicit `transitionToNext` receives `@videoml:auto:` plus compact JSON `["implicit-transition",fromSceneId,toSceneId]`, where the final element is null when there is no following scene. Consumers materialize this identity from the same adjacent source scene IDs. Explicit IDs are recommended for durable correspondence across edits and reordering. P17 binds portable source and artifacts by manifest hashes; normalization does not establish content identity.
